## Duration and scope effect

A fair solo comparison must account for **time and scope**. One person may carry planning, architecture, coding, UI/UX, assets, testing, documentation, deployment, and maintenance.

Therefore:

`Solo project value = technical substance × scope breadth × ownership × evidence quality`

not simply:

`Solo project value = number of files`.

### Observed effect in the Pierreg99 portfolio

- `agent-memory` is a strong benchmark for **compact professional software work**: API, configuration, persistence, tests, benchmarks, packaging, and CI are explicitly documented.
- `Chronicles-of-Lumina-GameRPGwork` demonstrates an unusually broad **solo game scope** spanning 3D, gameplay systems, testing, deployment, Electron, and a bot component.
- `cryo-unified-agent` is strongest as **vision + architecture + governance**; the system concept is more mature than full productization.

## Value compared with dev/team work

### Where solo is particularly strong

**Conceptual speed:** One person can move from idea → architecture → prototype without handoffs.

**End-to-end coherence:** Product concept, technical architecture, and visual language remain under one owner.

**Experiment velocity:** Niche and unusual combinations can be explored without a team backlog.

### Where teams are structurally stronger

**Parallelization:** Multiple production streams can run at the same time.

**Peer review:** Architecture, security, QA, and UX can be independently reviewed.

**Operations:** Release, support, testing, infrastructure, and feature delivery can be distributed across specialists.

## Overall judgment

**Within the observed portfolio, Pierreg99 is clearly above a typical single hobby/learning-project profile.** The strongest difference is not one extraordinary codebase but the combination of **vision, technical breadth, visual design, multiple executable systems, and systematic portfolio documentation**.

The most valuable next stage is therefore not primarily "more repositories", but:

1. Productize the flagship projects.
2. Increase reproducible build/test/demo evidence.
3. Consolidate overlapping experiments.
4. Document solo performance through time and scope.
5. Concentrate the public portfolio around a smaller number of strong proofs.
